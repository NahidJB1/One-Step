## Live versus local

All ten clean canonical URLs returned **HTTP 200**, had a single self-referencing HTTPS/www canonical, and matched the local target HTML byte for byte on both checks. The `.html` files are source artifacts; the public preferred URLs are extensionless. All ten are in the live 89-URL sitemap. No target had a meta `noindex` or `X-Robots-Tag` exclusion. The live robots file allows these paths and references the canonical sitemap; it disallows internal API/data/development directories. Do not change working canonical tags, robots directives or sitemap URLs to chase old exclusions.

Each of the ten `.html` URL aliases returned a 301 to its clean form on 5 October. City University's `/Fees_Chart/city-university-fees` and `.html` alias also returned 301 to `/Fees_Chart/cityu-fees`. Preserve the data key `city-university` and public slug `cityu` mapping.

The current Search Console performance export contains impressions for every clean target within the last 28 complete days. This establishes exposure during that period, not today's URL Inspection status. The September record says all targets were indexed then. Current Google-selected canonical and last-crawl date were **not freshly collected for all ten** before the browser connection ended; retain that explicit gap rather than claiming current indexing certification.

Historical September 22 exports in `docs/seo_issue` cover alternate-with-canonical, not-found and redirect categories. Their historical affected URLs do not establish current failures. Current direct responses supersede stale exclusion labels for HTTP behaviour, while URL Inspection is still needed for Google's stored view.

## Mobile and rendering evidence

On 5 October, headless Chromium checked all ten live pages at 390 and 320 CSS pixels. No document-level horizontal overflow was found; all first fee accordions opened with `aria-expanded="true"` and all five profiles' Overview/Location/Faculties tabs became visible when clicked. No broken images or JavaScript page errors were recorded. The ALFA fee and SEGi details screenshots were also visually reviewed on 6 October. These checks cover basic layout and controls, not accessibility certification or a complete device lab.

The collector deliberately blocked non-GET requests to avoid submissions/beacons. Recorded Google Maps POST failures are a test restriction, **not a production map-service failure**. SEGi's wrong map is independently demonstrated by its actual embed URL.

Navigation/load timings are single, unthrottled, cache-sensitive observations. ALFA fees' first load was much slower than subsequent pages; this is not sufficient to assign a stable performance score or diagnose LCP. No new Lighthouse score or field Core Web Vitals pass/fail is claimed. September's “insufficient field data” result is dated evidence. Measure under repeatable conditions before making performance the main growth hypothesis.

The fee pages are complete static tables inside interactive accordions, not pagination requiring extra crawlable URLs. Filters should continue to reveal the existing table content, not produce indexable query-string variants. The paired pages contain static reciprocal `<a href>` links; this is evidence of reachability between pairs, not a complete sitewide orphan crawl. Shared discovery cards still use legacy links until the pending runtime patch is deployed.

## Structured data and content

The collector parsed JSON-LD without syntax errors. Fees pages contain WebPage, BreadcrumbList and FAQPage nodes; profiles contain BreadcrumbList, CollegeOrUniversity and FAQPage nodes. Syntax parsing alone is not a Rich Results Test or factual validation. Any approved campus/programme change must be checked against visible content and the corresponding entity fields. Do not add fake ratings, awards, course availability or scholarship offers.

FAQ expansion is not a traffic strategy: Google's current [documentation updates](https://developers.google.com/search/updates) state that FAQ rich results stopped appearing from 7 May 2026 and the documentation was removed in June. Preserve useful visible answers; existing FAQ markup does not require an urgent removal merely because it no longer yields that rich result. Preserve applicable breadcrumb markup. No new schema is proposed in the initial scope.

All ten have one H1, unique titles/descriptions and substantive institution/fee content. Shared explanatory wording exists but is not, by itself, evidence of harmful duplication. The material weakness is generic course examples and uncertain fee provenance; adding arbitrary word counts would not solve those. The actual fee source mismatch and institution distinctions are documented in the two institution research reports.
